# 让新增 UI、设备与原版画面融合

这是明月的更好体验的开发经验整理，不是官方新增接口清单。来源为2026-11-08至09的本机代码研究和项目实践。顾客终端已被玩家确认能接入、存在轻微穿模；平板有实际截图依据，全部分辨率、拖放和存档流程尚未逐项实机验收。这里描述接入方法，不承诺“照抄即完美”。

## 先选正确的原生系统

| 需求 | 优先入口 | 应查询的原版代码 |
|---|---|---|
| 一句话结果 | 原生 Notify | StoreUIManager.Notify |
| NPC台词、玩家选项 | 原生 Dialogue／AddChoice | Dialogue、DialogUIManager |
| 平板管理页面、数字输入 | 克隆原生平板外框，使用原生控件 | EndOfDayUIManager、EndOfDayTabletFrame、CustomUIManager、CustomUIBuilder |
| 墙面装饰、小终端、挂墙武器入口 | 场景 SpriteRenderer，跟随实际场景锚点 | StoreUIManager.showcaseRenderer、StoreClientCounter |
| 能放入、取出实物的展示柜 | 柜体画面与真实库存分离 | PixelWindow、GameGridInventory、GameSlotInventory |
| 沿精灵透明边缘描边 | 原生场景交互与EPOOutline | Interactable、Shotgun；firstpass内Outlinable／OutlineTarget |
| 垃圾桶式矩形边框 | 单物品库存槽高亮 | GameSlotInventory.HighlightSlot、HighlightManager |

用 search_symbols 发现真实ID，再用 read_symbol 读取。字段、物品ID和调用片段也可用 search_source 查询。下文的名字必须以当前安装版本为准。

## 原生平板页面

1. 等局内管理器与资源就绪，从 EndOfDayUIManager 的 tabletPrefab 获取当前外框。
2. 查询 CreateWindow 的重载，使用它克隆外框；窗口ID带自己的Mod前缀，挂入现有UI层。只修改克隆体，不修改共享prefab。
3. 获取 EndOfDayTabletFrame，先校验content、footer、buttonHost、sectionHeader等实际用到的引用。缺失则关闭本次窗口并报告，不继续操作半成品。
4. 清理克隆体里的旧内容容器，沿用外框、标题、页脚、按钮样式。输入用 AddInput，按钮用原生回调，完成后 RebuildLayout。
5. 继承原生文字字体、材质与颜色；中文字体按游戏当前 FontLoader 配置处理。仅对自己的克隆文字停用会覆盖内容的 LocalizeStringEvent，不能全局关本地化。
6. 给克隆外框上的关闭按钮绑定关闭动作，避免重复绑定同一按钮。关闭和ESC都清窗口句柄、输入焦点、会话状态；重复打开前关闭自己的旧窗口。
7. 输入期间只更新对应值，不每次按键重建整个窗口。AddInput 的提交和逐字事件不是一回事，先核对 onChanged／onTyping。

“官方API创建的窗口”不自动等于“符合这个页面的视觉风格”。本项目曾用默认深色窗口做预算页，玩家明确认为违和；改为原生平板后才符合要求。

TabletUI、TabletStyle、ModuleScope是明月项目自己的辅助类，游戏本体不提供。新工程不能直接引用这些名字，应该复用自己项目中已有的辅助类，或通过当前官方构建器完成同样职责。

不要为了盖住层序问题新建Canvas、修改全局sortingOrder或接管全屏鼠标。新功能应跟随现有窗口系统、输入门禁与实际布局。

## 场景终端与装饰

1. 先判断对象只画画面，还是要点击、拖动、放物或参与武器业务。挂墙精灵不能替代真实枪械或设施。
2. 绘制与目标位置相符的原创像素图：像素密度、透视、光照、暗部、侧壁、接触阴影都要与相邻设备对应。屏幕图案也跟随面板透视。
3. 优先沿用原版场景渲染方式、材质和层序。克隆渲染对象前检查其全部组件与子对象；Instantiate组件也会复制所属GameObject，不能假定只复制一个组件。
4. 锚定电视、墙面或人数设备等实际参照物；不要直接写死屏幕像素坐标。跨UI／场景坐标时，使用真实Canvas相机与目标场景相机做投影。
5. 透明纹理的整张画布不等于设备可见范围。本机研究中有960×540完整透明画布，sprite.bounds不能用来推断可见柜体边缘；应按具体sprite的有效像素裁切。
6. 裁切必须对应同一个sprite。小柜的裁切框不能套给中柜；非九宫格原图保持Simple和比例，不能用Sliced强拉成正方形。
7. 像素图沿用Point采样、适当PPU与像素吸附。原图尺寸和实际显示尺寸应一起设计，随意使用0.75等缩放不保证所有像素边缘稳定。
8. 借用原版运行时纹理时，只持有引用，不能销毁共享纹理，也不要导出分发原版美术。退出场景只释放自己创建的对象、Sprite和贴图。

Real Time Clock的启发在于跟随电视所在场景、相对锚点与像素尺度，不是要求依赖或复制该MOD。

## 点击、拖动与放物

- 可见与可点击分别验证。现有PhysicsRaycaster／Physics2DRaycaster的eventCamera、finalEventMask、物理层和Collider都可能影响命中；渲染层序与物理命中不是同一件事。
- 复用现有pointer／动作派发。拖动遵守SECONDARY_CLICK改键，使用实际事件相机的射线与墙面相交；保存墙面相对位置，离店、失去目标或停用时清拖动状态。
- 设备的点击区应避开实际物品落点。展示柜可把开窗Collider放在顶框，内部区域留给原生拖放。
- 柜体只负责画外观。真正收纳需要原生库存图，放物规则尽量跟随展示台或存储区；业务白名单可在“发布”时检查，不要连正常放入都一律拦截。
- 保持原版物品格像素尺寸，让柜体适配格子。原生拖放按拖动物图形中心定位，单独缩小目标库存会造成“看起来对着格子却放不进”。
- 对齐采用grid.inner的实际原点与范围，再经相机和父Canvas换算，不能把世界坐标直接填进anchoredPosition。
- 拖放期间先记录待开窗，等拖动结束、输入／弹窗门禁允许再打开，避免窗口抢走正在进行的放置。

## 三种高亮不能混用

**场景轮廓**：Collider → Interactable悬停 → 自有Outlinable／OutlineTarget → 现有相机Outliner。Sprite的Alpha参与裁切，所以能沿外形描边。不要给整面墙绑定轮廓，也不要为一台设备修改全局描边相机。

**单槽矩形边框**：GameSlotInventory.HighlightSlot依据物品占格范围选择原生Border精灵。垃圾桶的外部边框来自外部单槽，不是垃圾桶纹理Alpha轮廓。

**内部逐格提示**：GameGridInventory.HighlightSlot按物品形状和能否放置绘制格子提示。红色可能表示不能取走或不能放入，不能一概判定为设备故障。

现有设备若已经处理PointerClick和拖动，再叠加Interactable可能重复打开窗口或抢走右键。选择单一点击入口；只需要描边时，不额外注册第二套点击逻辑。轮廓、Tooltip文字、绿色选中态也分别有不同职责。

## 保存、快捷键与生命周期

- 真实物品由原生保存图持久化，ModData存业务进度与身份。隐藏显示层不能销毁库存或复制样品快照。
- 发布后的库存槽序要稳定；不能因为视觉排序改变就重排保存索引。槽角色按明确坐标／索引识别，不按HashSet枚举顺序。
- 运行时扩格不意味着工厂下次自动恢复同样尺寸。本机SaveManager保存实物图与位置，没有保存这项扩容；读档后需按物品坐标和需求恢复自有库存尺寸，不移动既有物品。
- 常驻PixelWindow也会进入窗口管理。它曾使Enter按铃被“存在弹窗”门禁永久拦截；仅在自有快捷键判断中排除该常驻窗口的确切引用，保留其他弹窗与输入保护。
- 名称、市场参考价与操作资格分开。不能因为物品暂不支持悬赏，就连市场参考价也不显示；市场价、目录基价、顾客报价与成本要明确区分。
- 注册和清理对称：订阅／退订事件，清理自有句柄和回调，恢复动过的原生位置；不销毁借用的共享资源和持久物品图。

## 出问题先查什么

| 现象 | 优先检查 |
|---|---|
| 整台设备看不见 | 是否缩放了完整透明画布、激活状态、继承材质与层序 |
| 少右框、底框或透视变形 | 裁切是否匹配sprite、是否误用Sliced、缩放比例 |
| 可见但点不到 | 原生射线器、事件相机、mask、Collider与遮挡 |
| 放不进物品 | 是否真实库存、接收规则、原生格子尺度、点击区是否拦截 |
| 一点就开两次 | 是否叠加两套点击派发或重复注册监听 |
| 开柜后Enter失效 | 常驻窗口是否被计入临时弹窗 |
| 输入被打断 | 是否逐字重建窗口、关闭时焦点是否清理 |
| 读档后物品越界 | 工厂槽序、库存尺寸恢复、保存根和物品坐标 |

代码查询和编译只能确认各自范围；像素、遮挡、命中及拖放需实际运行画面分别确认，不为“使用这篇参考”额外启动一整套回归。
