# 原生人脉网络：注册、购买与实际效果

这是项目实践，不是官方API文档。日期：2026-11-10；来自明月的更好体验0.12.1／0.12.2。游戏更新后应查询本机实现，不能把本次时序限制扩展成所有版本的规定。

## 证据与确认范围

- 0.12.0真实日志：主菜单`AddNetworkUpgrade → RegisterModUpgrade → PlayerStore.Instance`触发构造空引用，模块随后停用。因此卡片不是“没画出来”，是注册时机错误。
- 0.12.1在`OnGameLoadedLate`及`OnNewGameStarted`注册后，玩家已确认王尔德网络显示新增水务升级。
- 玩家随后报告买下幽灵水后提示仍为铁锈水。物品详情0.9.3的龙头分析只读取原生当天水源字段，不查询MOD私有缓存。
- 0.12.2统一原生水源的修复已编写，实际购买后提示／装水、保存和换日仍待玩家复测。不要把“卡片出现”写成全部玩法通过。

## 研究入口

先查询官方`AddNetworkUpgrade`说明，再查本机：

```text
search_symbols(query="RegisterModUpgrade")
read_symbol(symbol_id=<实际返回的ID>)
search_symbols(query="Unlock")
read_symbol(symbol_id=<NetworkUpgrade所属的真实ID>)
find_references(member="FireOnGameLoadedInit")
```

本机`OnGameLoadedInit`在反序列化之前，不能把名字里的Loaded当成完整局内数据已就绪。需要已恢复购买状态用Late事件；新局另订阅`OnNewGameStarted`。`Init/OnEnable`安排订阅，`OnDisable`对称退订，不访问单例私有成员规避初始化。

## 注册与原生布局

官方调用形状示例，自己的`RefreshEffects`不是游戏API：

```csharp
ModHelper.AddNetworkUpgrade(
    modId, upgradeId, cost, "Water",
    () => "幽灵水直供",
    () => "将店内水龙头接入幽灵水管线。",
    RefreshEffects,
    iconKey: "RUSTWATER_TAP",
    prerequisites: new[] { "RUSTWATER_TAP" });
```

- `subtitle="Water"`决定原生水商分组，`tab`决定标签页。沿用原生卡片与图标，不自己画人脉窗口。
- 自定义ID带MOD前缀并保持稳定；二级升级以前级自定义ID为前置，不伪造原生解锁状态。
- 在载入完成和新局就绪回调中注册，并在同一入口恢复已经购买的效果。不要用进程级“一次注册”标记跳过其他存档的运行记录。

## 购买、保存和调价

当前本机`Unlock`先设置已购状态，再调用`onUnlock`。因此购买时立即应用效果；读档则查询状态恢复，不再扣钱或要求用户重新购买。

定义和运行记录不同：注册会更新定义，但已有运行记录不会自动被替换。调价可用`GetNetworkUpgrade(id)`更新运行记录的`cost`，保留其已购状态和历史；不要整个替换成默认未购买对象。

固定ID、同ID定义替换和运行状态保留，均需先核对当前本机实现。`RemoveNetworkUpgrades(modId)`移除的是MOD定义，不应被当作清除玩家购买记录的方法。

购买前保存的旧档不含后来的购买。用户未保存购买时，不要反复建议读旧档来修复“购买不立即生效”；先检查购买回调及效果读取路径。

## 水龙头案例：一个真实水源

原生装水在铁锈水升级已购时读取`StoreStation.todayRustwaterPurity`，物品详情0.9.3同样读取它。仅改说明或新增独立纯度缓存，会让提示继续显示旧水质；仅让部分容器走自有回调，也会分裂实际行为。

0.12.2采用：已购MOD管线生效时同步原生当日龙头字段，让装水、污染分配、过滤、混合、音效及水质提示沿用原生路径。没有补丁第三方内部类型，没有分发第三方DLL。

需要覆盖的时序：

1. 购买回调立即刷新。
2. 载入／新局就绪后恢复已购管线。
3. 原生`StartDay`重新随机当天水质后，再应用管线基准。
4. 净水片改变当天纯度时同步，次日恢复管线基准。
5. 清理按站点对象、局、日期和最后写入值核对，不覆盖其他后续改动。

这是本案例的实现选择，不是要求所有新增升级都改原生字段。检查字段所有消费者，确认只影响期望对象，再选最小改动。已有容器中的水不会自动升级，测试应使用空容器，注意过滤与混水。

## 排错顺序

卡片缺失查注册日志和生命周期；卡片显示但不能购买查前置、价格和原生状态；购买后无效果查`onUnlock`与实际使用者；提示不同查提示的数据来源；读档／换日丢效果查各自恢复入口。构建和扫描不替代这些实机结论。
